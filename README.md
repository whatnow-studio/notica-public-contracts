# Notica Public Contracts

Public, language-neutral distribution artifacts for Notica cross-runtime contracts.

## Authority

This repository is **not** a contract source of truth.

Authoritative Notica contract definitions live in the private `whatnow-studio/notica-backend` runtime/domain implementation. Public artifacts in this repository are deterministic public-safe projections generated by an approved Backend publication workflow.

Do not hand-author or manually edit published contract artifacts here.

## Consumers

The initial consumer is the open-source Python Worker:

- `HUIXIN-TW/NotionSyncGCal`

The Worker must consume only the minimum public-safe contract it requires. Private capability/commercial policy, quota and uniqueness records, write implementation details, provider payloads, credentials, secrets, and unrelated persistence internals are excluded.

## Distribution model

Published contract releases use immutable, contract-family-specific tags.

Initial convention:

```text
mapping-domain-v1.0.0
mapping-domain-v1.1.0
...
```

A release tag is a distribution identity. It does not replace:

- the contract module `schemaVersion`;
- the Backend artifact-set version;
- the artifact SHA-256;
- private npm package versions.

Consumers must pin an explicit immutable release/tag and verify the artifact SHA-256 recorded in the release manifest. A mutable branch or `latest` must not be the only compatibility identity.

## Repository shape

After the first approved publication, the repository will contain generated artifacts such as:

```text
mapping-domain/
└── v1.json
manifest.json
```

Normal consumer runtime must not fetch contracts from GitHub. Consumers should vendor an explicitly pinned release during an intentional dependency-update step, verify its digest, and run their own compatibility CI before deployment.

## Publication

Artifacts are published from an explicitly approved immutable commit of `whatnow-studio/notica-backend`.

Publication must:

1. regenerate and verify canonical Backend contract artifacts;
2. select only the public-safe projection;
3. verify schema and SHA-256 identities;
4. publish generated bytes to this repository;
5. create an immutable release/tag;
6. leave consumer adoption as a separate reviewed update.

Cross-repository publication credentials must use least privilege. Long-lived personal access tokens are not the default publication mechanism.
